# Asli relay

The server half of [Asli](../README.md). It forwards encrypted clipboard messages between a
person's own devices and can read none of them.

It is deliberately small: one process, no database, nothing written to disk, and no account system.
What it holds is a set of live WebSocket connections grouped into rooms, plus at most one recent
ciphertext per room so a device that was switched off can catch up.

## What it can and cannot see

It can see connection times, message timing, message sizes (padded into buckets by the client), and
IP addresses. It can drop or delay messages, because any relay can.

It cannot read clipboard content, forge a message, or join a room. It holds no per room secret and
no registration state: a client proves itself by signing a challenge with a key derived from the
account secret, and the room id is verified arithmetically as a hash of the public key. A stolen
copy of everything this process holds grants an attacker nothing beyond ciphertext and timing.

The full account is in [docs/THREAT_MODEL.md](../docs/THREAT_MODEL.md).

## Running it locally

Node 24 or newer.

```sh
npm install
npm start          # listens on http://127.0.0.1:8080, WebSocket path /v1
```

There is no build step. The sources are TypeScript and Node runs them directly using native type
stripping, which is why `tsconfig.json` sets `erasableSyntaxOnly`: it makes the type checker reject
any syntax that stripping cannot handle, so the failure shows up in CI rather than in production.

```sh
npm run typecheck  # tsc --noEmit
npm run lint
npm test
```

The test suite includes an end to end check that starts the relay, connects two real clients, and
asserts that a clip reaches the peer and not the sender. The authentication tests run against
`testdata/vectors.json`, which is generated by the Rust crate, so a failure there means the two
implementations disagree about the wire format.

## Self hosting

```sh
docker compose up -d
```

Edit the hostname in `Caddyfile` first. Caddy obtains a certificate automatically, so there is no
certificate management step.

The compose file is the same one the public relay runs. Self hosting is meant to be identical
rather than a downgraded variant, so if you need higher limits, raise them here and point your
clients at your own relay in Settings.

## Configuration

Every limit is an environment variable, and the server refuses to start rather than clamping a
nonsense value. The defaults are the public relay's.

| Variable | Default | Meaning |
|---|---|---|
| `PORT` | 8080 | Listen port |
| `HOST` | 0.0.0.0 | Listen address |
| `METRICS_PORT` | 9090 | Prometheus style counters, bound to loopback. Set to 0 to disable |
| `LOG_LEVEL` | info | debug, info, warn or error |
| `MAX_FRAME_BYTES` | 1 MiB | Largest accepted WebSocket frame |
| `MAX_CONTENT_BYTES` | 700 KiB | Content cap announced to clients. Base64 expansion is why it is not 1 MiB |
| `RETAIN_MAX_BYTES` | 64 KiB | Messages above this are forwarded live but never stored |
| `RETAIN_GLOBAL_BUDGET_BYTES` | 256 MiB | Ceiling across all rooms, with least recently used eviction |
| `RETAIN_TTL_MS` | 24 hours | How long a stored clip survives |
| `MAX_ROOMS` | 100000 | Refuse new rooms past this |
| `MSG_BURST`, `MSGS_PER_SEC` | 10, 2 | Per connection message rate |
| `BYTE_BURST`, `BYTES_PER_SEC` | 2 MiB, 256 KiB | Per connection byte rate |
| `ROOM_BYTES_PER_DAY` | 50 MiB | Per room rolling quota |
| `MAX_CONNS_PER_IP` | 20 | Concurrent connections per address |
| `MAX_CONNS_PER_ROOM` | 16 | Concurrent connections per room |
| `MAX_CONNS_GLOBAL` | 10000 | Hard ceiling |
| `TRUSTED_PROXY_CIDRS` | empty | Comma separated. Required for `X-Forwarded-For` to be honoured at all |

### A note on `TRUSTED_PROXY_CIDRS`

If it is unset, `X-Forwarded-For` is ignored completely, which is correct: the header is attacker
controlled. Behind a proxy that means every connection appears to come from one address and per IP
limits become global limits, so set it to your proxy's network. The chain is then walked right to
left and the last entry added by a trusted hop wins. The first entry is never used, because that is
the one a client can write freely.

## Running a public relay

Operating an open relay means running a free, anonymous, encrypted blob forwarder. That is
attractive to people who want a covert channel rather than a clipboard. The defaults are what keep
that impractical: a small retained size, a short TTL, a per room daily quota, connection caps, and
memory only storage.

If you run one publicly, publish an abuse contact and a short statement of what the relay retains,
which is 24 hours of one ciphertext per active room and aggregate counters. Both of those are worth
having written down before the first complaint arrives rather than after.

## Logging

Logs are an allowlist, not a redaction pass. Every record is assembled from named fields: a salted
room identifier, an event name, a byte count, a message id, a connection count and a coarse error
code. Clipboard content and ciphertext never reach the logger, and the room salt is regenerated per
process so log lines cannot be correlated across restarts.
